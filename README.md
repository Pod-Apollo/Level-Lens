Level Estimator

Prototype Accessibility Evaluation Planning Tool

Overview

Level Estimator is a browser-based prototype designed to help accessibility practitioners, project managers, and clients estimate the potential effort required to evaluate a web page.

The tool analyzes page structure, interactive components, regions, and common accessibility-related patterns to provide an estimate of page complexity and evaluation scope.

Important: Level Estimator is a planning and estimation tool. It is not an accessibility conformance testing tool and does not determine WCAG compliance, severity, or accessibility risk.

Prototype Status

⚠️ This tool is currently a prototype.

The current version is intended to:

Explore complexity estimation concepts.
Support accessibility evaluation planning.
Help identify potential testing scope.
Gather feedback from testers and stakeholders.
Validate estimation scoring and terminology.

The estimates generated by the tool should be considered directional guidance rather than definitive measurements.

Installation (Tampermonkey)
Prerequisites

Install the Tampermonkey extension:

Chrome: https://www.tampermonkey.net/
Microsoft Edge: https://www.tampermonkey.net/
Firefox: https://www.tampermonkey.net/
Install the Script
Install Tampermonkey.
Open the Tampermonkey Dashboard.
Select Create a new script.
Remove the default template code.
Paste the complete Level Estimator userscript.
Save the script (Ctrl + S or File → Save).
Ensure the script is enabled.
Navigate to a supported webpage.

The Level Estimator panel should automatically appear.

Using the Tool
Run an Estimate
Open a webpage.
Wait for the page to fully load.
Open the Level Estimator panel if hidden.
Review:
Page Complexity Summary
Current Scope
Estimate Detail
Evaluation Effort indicators
Hide the Tool

Depending on the installed prototype version:

Use the built-in Hide/Pause control, or
Use the assigned keyboard shortcut to restore the tool after hiding it.
Current Limitations

As a prototype, Level Estimator has several limitations:

Cannot determine WCAG conformance.
Cannot identify all custom component implementations.
May underestimate complexity in highly dynamic applications.
May overestimate complexity when reusable components are heavily repeated.
Does not replace manual accessibility testing.
Scoring logic should continue to be calibrated using real-world testing data.
Known Assumptions

The current estimation model assumes:

More interactive elements generally increase evaluation effort.
Custom components require additional investigation.
Dynamic behavior often requires deeper testing.
Complex workflows require broader evaluation coverage.
Rich media may introduce additional testing requirements.

These assumptions are subject to refinement as the prototype evolves.
